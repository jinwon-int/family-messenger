# 개발 순서

[제품 비전](VISION.md)의 첫 목표는 가족방 하나에서 가족과 AI 한 명이 함께 대화하고,
기억을 관리하고, 작은 일을 끝내는 경험이다. 2026-09-13 [결정 D](DECISION-2026-09-13-MATRIX-CRYPTO-STACK.md)에
따라 전달·암호화는 Matrix 스택을 채택하고 화면·AI 층을 직접 만든다.
아래는 개발·인수검사 순서이며 완료 목록이 아니다. **진행 추적과 결정에 이른 대화 기록은
[이슈 #92](https://github.com/jinwon-int/family-messenger/issues/92)에 있으며, 이 문서와 어긋나면 #92가 우선한다.** **각 단계의 착수는 앞 단계의 KPI 게이트를
숫자로 통과했을 때만 허용한다** — "그 방향으로 무한히 깊게" 가는 것을 막기 위한 장치다.

## 0. 멈추고 정리 (약 2주)

- 네이티브 MLS·successor 작업 **동결**. 스키마 13 추가 금지. 해당 코드·실험을 `archive/`로 이동, `mls-experiment.yml` 비활성화.
- `server/*-evidence.json`·PR별 문서를 `docs/evidence/`로 이동.
- CI 예산 복구: 팬아웃 job 통합, apt/npm 캐시. `test_mls_assets` 11중 복제 정리.
- Go 서버 운영 형태 최소치: `/health` 인증 밖, 구조화 로그, 오류 ID, 설정 파일, systemd 유닛.
- **홈서버 1주 평가**(Tuwunel 1순위 / continuwuity 대안) — 결정 문서의 항목표로. 운영 Synapse는 건드리지 않는다.
- 플릿 `SafetyStop` 해제 CLI, `backup.py` 하드코딩 호스트 제거, 예외 로깅에 원인 포함.
- `docs/README.md` 인덱스, Python 린터·타입 검사, 3.11 하한을 CI에서 실제 검증.
- 운영 Matrix(Synapse) 안전망 추가 투자는 하지 않는다 — 1단계에서 교체된다. 백업 타이머만 유지.

**게이트:** 홈서버 평가표 전 항목 "확인함". CI 총 예산이 결정 시점 대비 절반 이하.

## 1. 가족과 AI가 함께 대화 — E2EE로 (약 6~8주)

- 선정 홈서버를 운영 호스트에 단일 바이너리로 배포(전용 CF 터널, 공개 가입·게스트·federation 차단, 방 암호화 기본). Synapse의 메시지가 0건이므로 이관 없이 계정만 재생성.
- **우리 웹 화면**: `matrix-js-sdk`(Rust 암호화 WASM) 기반. 한국어·휴대폰 우선·PWA 설치. 개인방·가족방, 텍스트·사진·영상·일반 파일. 기기 검증(이모지 비교)·복구 키 생성/보관 안내를 가족 수준으로. 사람과 AI 참여자 구별 표시.
- **AI 한 명**: AI 참여 노드가 `fleet_matrix.py`로 가족방 참여. `room_gate`에 가족방 모드(허용 가족 + 봇 1) 추가, `fleet_core`의 mention 모드를 어댑터에 연결. 명시적 호출에만 응답. 초대 시 "이 AI가 읽는 범위·제공업체 전달 범위" 안내(원칙 1).
- 에이전트 런타임은 ccc-node `bridge/core/agent_runtime.py`·`bot_ports.py`를 정식 인터페이스로 승격해 재사용(현재 out-of-repo import 제거, Telegram 타입 결합 제거).
- 백업: 홈서버 온라인 백업 + media 디렉터리를 restic 쌍으로. **복원 드릴 스크립트 포함.** 저장·백업 실패는 Telegram으로 푸시.
- Synapse/Element/Postgres 컨테이너 퇴역, `compose.yaml`·`init.py`는 새 홈서버용으로 대체.

**게이트:** 가족 2명 + AI 1이 가족방에서 **실제 대화 100건**(E2EE, 두 기기). 복원 드릴 1회 성공. 이 숫자 전에는 2·3단계 착수 금지.

## 2. 실제 기기 인수검사 (약 4주)

- 실제 Android/iOS 브라우저·PWA: 백그라운드·저장소 축출·잠금화면 노출 범위. 데스크톱 headless 통과는 인정하지 않는다.
- 푸시 알림(sygnal 또는 홈서버 내장 경로) 수신 지연·중복·오프라인 복귀.
- 기기 분실 시나리오: 새 기기 검증, 복구 키로 이력 복구, 전 기기 분실 시 재등록 안내.
- 사진·영상 실기기 열람·재생, 용량 초과 안내, 전송 실패 후 중복 없는 재시도.

**게이트:** 가족 실기기 2종에서 위 항목 전부 통과 기록.

## 3. 확인받고 기억하고 실행 (약 6주 · 2단계와 병행 가능)

- 기억 서비스(우리 Go 서버): 저장 전 확인 → 출처·개인/가족 공유 범위 표시 → 조회·수정·삭제. E2EE 방이므로 **기억의 원문은 에이전트 노드 측**(그 노드가 방의 기기)에 두고 서버는 색인·권한·감사만 갖는다. 원문 대화 삭제와 파생 기억 삭제를 구분해 설명.
- 실행 승인: 대상·내용·영향 미리보기 → 승인·거절·취소·진행·결과 → 재접속 후 중복 실행 금지. `fleet_core`의 admission·outbox·uncertain 계약 재사용. 첫 도메인은 일정·할 일 둘만.
- 개인 대화를 가족방에 공유하기 전 당사자 확인.

**게이트:** VISION 수용 기준 2~4번을 실사용 가족이 시연.

## 4. 여러 AI 에이전트로 확장 (약 4주)

- 에이전트 레지스트리(신원·역할·허용 방·실행 권한)를 배포 설정으로. 계정·기기 발급 스크립트화.
- 공용방 명시적 지목 응답, 동시 실행 상한, 봇-봇 연쇄 금지, 노드 단절·취소·복구.
- 운영 AI 노드 → 나머지 11개. Telegram 이중 전송 확인 후 주 통로 전환. [에이전트 연결 설계](FLEET-BRIDGE.md) 재사용.

**게이트:** 12개 노드 실제 응답, 지목 안 된 노드 침묵 확인.

## 5. 재검토 지점

1~4단계를 겪은 뒤 "Matrix 스택이 실제로 우리를 어디서 아프게 했나"를 데이터로 갖고 전달층 자체화를
다시 판단한다. 그 전에는 판단하지 않는다.

음성·영상 통화는 현재 범위 밖이다. 기존 대화 기록 이관은 별도 동의와 대상 선정 후 진행한다.
공개 저장소는 코드와 합성 검증 자료를 위한 공간이며 운영 데이터 이전을 수행하지 않는다.

## 일정과 병목에 대한 정직한 메모

합계 약 5개월, 가족 첫 E2EE 메시지는 2개월째가 목표다. 속도의 병목은 코딩이 아니라
**리뷰·실증**이다(2026-09-12 #16 실증은 "재검토 1회 소진 → 대기"로 하루를 썼다). 단계마다
인수검사 담당 노드를 작성 노드와 분리해 지정한다.
