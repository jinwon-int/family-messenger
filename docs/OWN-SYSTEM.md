# 직접 만드는 가족 메신저 — 2026-09-08 방향 변경

운영자는 기존 메신저 스택 의존성을 줄이고, 좋은 공개 저장소는 벤치마크만 하면서
서버와 화면을 직접 만드는 방향을 요청했다. 기존 Matrix 확대 후속 실행은 취소했다.
이 문서는 새 구현 계획이며 자체 서버가 이미 운영 중이라는 뜻이 아니다.

## 유지할 요구

- 육손에 메시지와 사진·영상·일반 파일을 저장한다. 음성·영상 통화는 제외한다.
- 가족 개인방·단체방과 플릿 작업방을 구분한다. 플릿은 12개가 각자 신원으로 참여한다.
- 서버 작업 허용자는 운영자이며, 가족 계정의 채팅 권한을 서버 실행 권한으로 확대하지 않는다.
- 노드의 AI/실행 환경과 자격 증명은 원래 노드에 유지한다. 재시도·중복·승인·취소·원격 종료를 검증한다.
- 새 구현이 인수검사를 통과할 때까지 현재 서비스·데이터·백업을 보존한다.

## 우선 검토할 구성

| 부분 | 제안 | 선정 이유/검증할 점 |
|---|---|---|
| 서버 | Go 표준 HTTP 서버와 자체 API | 웹/API/이벤트 스트림을 한 실행 파일에서 제공. 성능·메모리 수치는 실측 후 기록 |
| 웹 | 직접 만든 HTML/CSS/JavaScript, 서버에 포함 | 화면 빌드 도구·대형 UI 프레임워크 없이 시작. 실제 휴대폰에서 조작성 검사 |
| 실시간 전달 | HTTP POST + SSE | 브라우저 표준 EventSource로 수신. 재접속 cursor·권한 변경·느린 소비자·CF 경유 연결을 시험 |
| 저장 | SQLite + 첨부 디렉터리 | 별도 DB 서버 없이 시작. WAL·경합·마이그레이션·백업 복원 검증. DB 엔진은 직접 만들지 않음 |
| 계정 | 검증된 인증과 앱 자체 권한 검사 | 현재 인프라에 맞춘 CF Access 연동을 우선 검토. 방·파일·플릿 권한은 앱이 별도 확인 |
| 플릿 연결 | 자체 이벤트 계약 + 기존 worker/guardian | 특정 채팅 프로토콜을 거치지 않고 작업·진행·승인·취소·최종 결과를 전달 |
| 암호화 | 보안 수준을 명시하고 검증된 구현 선정 | 종단간 암호화 여부는 아래 별도 경계. 자체 암호 프로토콜을 만들지 않음 |

새 채팅 런타임의 기본 목표는 앱 프로세스 하나, SQLite 파일, 첨부 디렉터리다.
이 숫자는 총 의존성이 0이라는 뜻이 아니다. SQLite 드라이버, 인증·암호화 라이브러리,
운영체제, TLS/프록시, 백업 도구와 모바일 알림 기반 시설은 별도 목록에 기록한다.
Go는 우선 제안이며 아직 새 서버 코드·도구체인·벤치마크가 준비됐다는 뜻은 아니다.

## 벤치마크 근거

2026-09-08 공식 GitHub README/API 문서를 gh CLI로 확인했다. 이 비교는 설계 비교이며
처리량이나 메모리 성능을 측정한 벤치마크가 아니다. upstream 코드는 이번 변경에 복사하지 않았다.

| 참고 프로젝트 | 확인한 내용 | 우리 구현에 참고할 점 |
|---|---|---|
| [Tinode](https://github.com/tinode/chat), [API](https://github.com/tinode/chat/blob/master/docs/API.md) | Go 서버, 개인/단체 대화, topic별 순차 ID와 접근 권한 | 방별 메시지 순서, 동기화 cursor, 읽음 상태, 멤버 권한. 서버 자체와 연합/통화 기능은 도입 대상 아님 |
| [ntfy](https://github.com/binwiederhier/ntfy), [구독 API](https://github.com/binwiederhier/ntfy/blob/main/docs/subscribe/api.md) | HTTP JSON/SSE 스트림, EventSource, since 재수신 | 끊김 후 수신 재개와 단순한 이벤트 전달. 알림 topic을 가족 대화방 권한 모델로 그대로 사용하지 않음 |
| [Gotify](https://github.com/gotify/server) | REST 전송·WebSocket 수신, 사용자/클라이언트/앱 구분 | 사람 계정과 플릿 발신 신원 분리, 단순한 서버 운영. 완성된 가족 그룹 메신저로 간주하지 않음 |

기능과 인터페이스를 참고하고 구현은 요구사항과 자체 테스트에서 출발한다.
나중에 코드나 자산을 가져오면 해당 버전의 라이선스를 검토하고 THIRD_PARTY.md에 기록한다.

## 직접 소유할 계약

1. **메시지:** 방별 순서, 작성자/장치, 클라이언트 요청 ID, 서버 수신 시각을 저장한다.
   같은 요청 ID의 재전송은 중복 저장하지 않으며, ID가 같은 다른 내용은 거부한다.
   DB 커밋 후 성공을 반환하고, 연결 복구는 저장된 이력에서 재개한다.
2. **권한:** 모든 이력·이벤트 스트림·첨부 요청에서 계정과 방 멤버십을 확인한다.
   탈퇴/정지 시 기존 스트림도 차단한다. CF 이메일 헤더만 믿지 않고 서명·issuer·audience·만료를 검증한다.
   CF를 교체해도 메시지/방 데이터와 플릿 ID가 바뀌지 않도록 앱 내부 ID를 유지한다.
3. **첨부:** 인증된 업로드/다운로드, 용량 한도, 무결성, 임의 경로 거부,
   실패한 업로드 정리·보존 규칙을 구현한다. 원래 파일명을 저장 경로로 쓰지 않는다.
   사진과 영상은 실제 두 기기에서 열람·재생을 확인한다.
4. **플릿:** 노드 신원·방·운영자·작업 ID를 결합한다. 승인/취소는 긴 작업 뒤에 대기하지 않는다.
   공용방에서는 명시적으로 지정한 노드만 응답한다. 불확실한 실행은 자동 재실행하지 않는다.
5. **운영:** 상태 점검, 저장 한도, 암호화 백업, 별도 환경 복원과 이전 버전 복귀를 검증한다.
   SQLite와 파일의 백업 시점을 맞추고, 백업 실패를 정상으로 표시하지 않는다.

## 암호화와 의존성의 경계

HTTPS와 암호화 백업은 종단간 암호화(E2EE)가 아니다. 서버가 메시지를 복호화하는 구조라면
서버 운영자는 내용을 읽을 수 있다. 기존 구성의 E2EE를 알리지 않고 제거하지 않는다.
운영자에게 유지 여부를 질문했으며, 답변 전에는 **E2EE 유지가 기본 요구**다.

E2EE를 유지하면 검증된 라이브러리 외에도 여러 장치의 키 배포, 장치 폐기, 그룹 키 변경,
오프라인 수신, 첨부 키, 복구 절차가 필요하다. WebCrypto 같은 암호 연산 API만 사용했다고
메신저 암호 프로토콜이 검증되는 것은 아니다. 라이브러리·라이선스·브라우저/모바일 지원을
선정하고 실패/복구 검사를 통과하기 전에는 보안 구현 완료로 표시하지 않는다.

플릿 작업방은 해당 AI 노드가 요청을 읽으며 필요한 내용이 AI 제공업체에 전달될 수 있다.
가족방에는 봇을 자동으로 추가하지 않는다. 모바일 백그라운드 푸시는 브라우저/OS 정책과
푸시 서비스에 의존하므로, 연결 중 SSE 전달과 별도의 수용 기준으로 둔다.

## 기존 작업 재사용

- `fleet_core.py`: admission·중복 방지·대기열·outbox·uncertain의 동작 규칙과 회귀 테스트.
- `fleet_worker.py`: 실제 노드 실행부와 승인·취소 계약. 현재 CLI가 Codex read-only 시험용이라는 제한은 유지한다.
- `fleet_remote.py`: SSH heartbeat·종료 증거와 Linux cgroup 실행 방식.
- `fleet_matrix.py`의 Matrix SDK·장치 동기화 부분은 새 프로토콜의 필수 의존성으로 가져오지 않는다.
- 기존 테스트와 검토에서 발견한 실패 사례를 새 구현의 수용 검사로 옮긴다.

Go 서버에서 Python 모듈을 직접 import할 수는 없다. 첫 단계에서는 고정 stdio worker를
유지하고, 저장/전달 계약을 새 서버에서 구현한다. 언어를 하나로 맞추기 위한 재작성은
실행 환경 안정성을 확인한 뒤 별도로 판단한다.

## 구현 순서와 통과 조건

1. `server/`·`web/app/`에서 자체 HTTP/저장/화면의 격리 시험 버전을 만든다.
   합성 계정·대화만 사용하고 로그인/권한·재시작 후 이력·중복 요청을 검사한다.
   직접/간접 패키지 목록과 서버 프로세스 수를 기록한다.
2. SSE 재접속·읽음·개인/단체방과 사진·영상·파일을 완성한다. 실제 두 클라이언트에서
   순서·중복·비멤버 차단·멤버 퇴장·파일 무결성·영상 재생을 검사한다.
3. 선택한 인증/E2EE와 키 복구, 일관된 암호화 백업·복원, 모바일 동작을 검증한다.
   개발 중 합성 평문 시험이 있다면 E2EE 구현으로 표시하지 않는다.
4. 새 프로토콜로 서서 실제 작업·승인·취소·끊김을 검증한 뒤 나머지 11개를 확대한다.
5. 기능·보안·복구 인수검사 후 운영 경로를 전환한다. 실제 데이터 이관 대상·복구점과
   실패 시 돌아갈 경로를 먼저 확정하며 기존 데이터/키를 자동 삭제하지 않는다.

현재 Matrix 첫 로그인/시험방 초대 수락은 새 자체 시스템 개발의 선행 조건이 아니다.

## 첨부 시험판의 저장 선택

첫 비공개 첨부 API는 파일당 8 MiB·전체 128 MiB 범위에서 SQLite BLOB과 메타데이터를
한 번에 커밋한다. 외부 파일과 DB의 저장 시점이 어긋나는 복구 절차를 줄이기 위한
시험판 선택이다. 별도 미디어 디렉터리와 대용량 운영 구조는 실측 후 판단한다.
브라우저 UI는 두 Chromium 클라이언트에서 합성 사진 표시·영상 재생·다운로드와
응답 유실 후 중복 없는 재시도를 검증한다. 실제 휴대폰과 E2EE 검증은 남아 있다.
[계약·복구·브라우저 검증 범위](../server/MEDIA.md).

## 계정 인증 경계 시험

CF 형식의 서명 토큰을 검증하는 별도 구성요소와 자체 방·파일 API 연결을
합성 계정·로컬 HTTP로 시험한다. 등록된 사용자 ID만 앱 계정에 연결하며,
이메일·role 주장만으로 운영자 권한을 부여하지 않는다. 실제 CF 설정이나
사람의 로그인은 아직 연결하지 않았다. [검증·의존성·남은 작업](../server/AUTH.md).
