## 발견

- **`TypeError: Load failed`(Safari fetch 네트워크 오류)**: 02:0x 홈 이탈 뒤 보내기에서 발생, 페이지 새로고침 + 같은 암호로 워커
  재시작 후 정상(봇 echo seq 10). 릴레이·터널·봇은 그 시간대에 정상(공개 경로 302, loopback 200, 봇 커서 불변). 원인은
  (a) Access 쿠키 유실 → 로그인 페이지(타 도메인)로의 리다이렉트를 fetch가 TypeError로 보고, 또는 (b) 네트워크 전환 일시
  실패 중 하나 — 로그인 화면 재등장 여부는 **오너 미확인**(질문했으나 답 없음). 클라이언트 개선: fetch 네트워크 오류를
  "연결 실패 — 새로고침 후(필요하면 로그인) 같은 암호로 워커 시작"으로 안내하고, 보내기 실패 시 입력을 보존한다.
- 봇 echo 시각과 오너 진술로만 복귀 해독을 증명한다(iPhone 화면 캡처 없음).
- **새로고침 뒤 이전 대화 미표시(2차, #258)**: `relay-app.js`는 `relaySeq`를 localStorage에 저장하고 이어하기 때 `events?after=relaySeq`만 가져오며 복호화된 본문은 저장하지 않는다 → 과거 메시지는 재표시되지 않는다(설계·명세 부재). 오너는 이를 실패로 인지했다 → 안내 문구 또는 로컬 이력 보존(평문 보존 범위 명시) 결정 필요. 운영자 안내문도 "이전 대화가 다시 보이면"을 조건으로 적어 혼선을 키웠다(교훈: 조건은 소스로 먼저 확인).
- 백그라운드 이탈 시간은 릴레이에 요청 로그가 없어(Safari 정지 중 폴링 없음) 오너 진술 + 지시/송신 시각 차로만 상한을 둔다.
