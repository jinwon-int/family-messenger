# Matrix 봇의 기기 변경 후 복구

웹앱 재로그인이 새 기기를 만들면 봇은 기존에 승인한 기기 집합이나 키와 다른 것을
감지해 멈춘다. `owner-device-set-changed`, `owner-device-key-changed`,
`pinned-device-missing`, `pinned-device-key-changed`는 신뢰 재확인 사유다.
설정만 바꿨을 때의 `saved-policy-changed`도 의도된 중단이다.
반복 재시작이나 `--initialize`는 이 검사를 우회하는 복구 방법이 아니다.

이 절차는 운영자가 승인받은 변경을 수동으로 적용하는 지침이다. 서버에 새 기기가
보인다는 이유만으로 자동 승인하거나 키를 덮어쓰지 않는다. 실제 계정, 장치 키,
토큰, 상태 DB와 호스트 경로는 비공개 운영 기록에만 보관한다.

## 확인과 백업

1. 기기 소유자에게 재로그인·기기 추가·기기 삭제 사실을 확인한다. 예상하지 못한
   변경이면 중단 상태를 유지하고 조사한다.
2. `/_matrix/client/v3/keys/query` 결과의 기기 ID와 ed25519·curve25519 공개키를
   해당 사용자의 실제 기기 정보와 독립된 신뢰 경로로 대조한다. 서버 응답만으로
   신뢰를 결정하지 않는다. 교체 전후 기기와 승인 범위를 비공개 기록에 남긴다.
3. 봇과 해당 상태를 사용하는 worker를 정상 종료하고 프로세스 종료를 확인한다.
   설정과 **전체 상태 디렉터리**를 일관된 시점에 백업한다. 디렉터리 0700·파일
   0600, 기존 실행 사용자, 암호화 백업을 유지하고 복구본을 확인한다.
   SQLite WAL·crypto 저장소·미완료 작업을 함께 보존한다.

## 설정과 저장 정책을 함께 변경

1. 승인된 차이만 설정의 `devices` 또는 `family_devices`에 반영한다.
   소유자 `devices`는 서버의 전체 기기 집합과 일치해야 한다. 가족
   `family_devices`는 승인한 기기만 포함한다. 이 둘의 범위를 혼동하지 않는다.
2. [Frontend 초기화 코드](../scripts/fleet_matrix.py)의 현재 정책 구성과
   `family_config` 정규화에 따라 변경 전후 정책을 계산하고 대조한다.
   저장 DB의 `meta.policy`가 승인된 변경 전 정책과 일치할 때만, 같은 트랜잭션에서
   승인된 변경 후 정책으로 갱신한다. 현재 정책의 필드:
   `owner`, `rooms`, `devices`, `worker_argv`, `not_before_ms`,
   `remote_worker`, `worker_argv_family`, `family_rooms`, `family_users`,
   `family_devices`. 과거 스키마의 기본값 처리도 같은 초기화 코드와 맞춘다.
3. 기기 변경에 방·worker·기준 시각 변경을 섞지 않는다. 예상 밖 정책 차이,
   다른 실행 중 프로세스, 스키마 불일치가 있으면 중단한다. 설정과 DB 중 하나만
   갱신된 경우에도 봇을 기동하지 않는다.

`crypto_store`, `device_identity`, pending inbox/outbox, sync cursor를 지우거나
초기화하지 않는다. 봇 계정·기기·토큰을 교체하는 작업은 별도 이전 절차다.
저장 정책 검사를 제거하거나 불일치를 자동 수용하도록 코드를 바꾸지 않는다.

## 기동 후 검증과 되돌리기

1. 동일 봇 기기·crypto 상태로 기동한다. 시작 직후 health만 보지 말고, 다음
   장치 pin 검사와 실제 sync가 끝난 뒤에도 `ready`인지 확인한다.
2. 승인된 시험에서 암호화 수신·응답과 인증된 발신 기기를 확인한다. 개인방은
   직접 요청, 가족방은 명시적 멘션 규칙을 적용한다. 멘션 없는 가족방의 무응답은
   전달 실패 증거가 아니다. 보류 작업을 임의로 다시 실행하지 않는다.
3. 재실패하면 중단하고 원인을 기록한다. 새 sync나 crypto 변경이 있기 전에는
   검증한 백업의 설정과 상태를 함께 복구할 수 있다. 새 연산이 있었다면 crypto
   상태를 과거로 덮어쓰지 말고 현재 상태도 보존한 채 별도 복구 판단을 받는다.

웹앱에는 복호화 실패 표시와 지연 복호화 재렌더 경로, 로그아웃 및 기기 관리 UI가
있다. 이것은 수신 실패를 보이게 하고 기기를 관리하는 기능이며, 봇의 독립된
기기 신뢰 확인을 대신하지 않는다. 관련: [연결부](FLEET-MATRIX.md),
[웹앱](WEB-APP.md), [#123](https://github.com/jinwon-int/family-messenger/issues/123).
